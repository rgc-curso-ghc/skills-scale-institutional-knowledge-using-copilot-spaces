# OctoAcme Project Management Docs

## Overview
This directory contains the complete OctoAcme project management framework—a set of lightweight, team-proven processes for delivering products and features. Whether you're starting a new project, planning iterations, or wrapping up work, these guides provide structured approaches to ensure alignment, quality, and continuous improvement.

## Project Lifecycle
OctoAcme projects follow these phases:

1. **Initiation** – Validate business need, align stakeholders, and decide to proceed
2. **Planning** – Break work into shippable increments, estimate scope, and plan releases
3. **Execution** – Build, test, review, and iterate with regular feedback
4. **Release** – Deploy to production with quality gates and monitoring
5. **Close & Retrospective** – Capture learnings and improve processes

## Core Principles
- **Customer-first** – Prioritize customer value and usability
- **Iterative delivery** – Deliver small, testable increments
- **Clear ownership** – Every project has clear roles and accountability
- **Data-informed decisions** – Measure impact and iterate based on evidence
- **Psychological safety** – Encourage feedback and continuous improvement

## Quick Reference: Key Roles

| Role | Key Responsibilities |
|------|---------------------|
| **Project Manager (PM)** | Coordinates delivery, manages schedules, risks, and communications |
| **Product Manager (PdM)** | Defines outcomes, prioritizes backlog, measures success |
| **Developers** | Implement features, collaborate on design and testability |
| **QA/Testing** | Validate quality and acceptance criteria |

For detailed role definitions and responsibilities, see [Roles and Personas](octoacme-roles-and-personas.md).

## Communication Cadence
- **Daily standups** – Team-level progress, blockers, dependencies (15 min)
- **Weekly sync** – PM + PdM alignment on delivery and priorities
- **Twice-weekly delivery standups** – Or as agreed by team
- **Monthly stakeholder updates** – High-level progress and status
- **Ad-hoc escalations** – As needed for blockers and risks

## Key Artifacts Used Across Lifecycle
- Project Charter / One-pager
- Roadmap and Release Plan
- Sprint/Iteration Backlog
- Acceptance Criteria & Definition of Done
- Risk Register
- Retrospective notes and action items
- Release Notes
